# B12X_ATTN: 1.41x prefill speedup at 131k, the first lever to move the quadratic term

**Date:** 2026-08-19. A/B test: `/tmp/attn-ab.sh`, `/tmp/b12x-attn-test.sh`,
`/tmp/attn-verify.sh`.

## Finding

Switching the attention backend from `TRITON_ATTN` (default) to `B12X_ATTN`
(b12x's native paged GQA backend for SM120) with `--block-size 128`:

| depth | TRITON_ATTN | B12X_ATTN | speedup |
|---:|---:|---:|---:|
| 2,049 | 9,577.8 | 9,907.1 | 1.03x |
| 32,769 | 5,980.2 | **7,108.7** | **1.19x** |
| 131,073 | 2,600.5 | **3,665.8** | **1.41x** |

Both profiles are `throughput` (all-FP4), same weights, same launcher, same
GPU. The only change is `ATTN_BACKEND=B12X_ATTN BLOCK_SIZE=128`.

B12X_ATTN boots successfully at 249,600 context (same as TRITON_ATTN). The
attention block size is set to 1664 by the engine to ensure attention page
size >= mamba page size (same alignment logic as prefix caching).

## Why this matters

The nsys round-3 traces showed `unified_attention` is 74.7% of prefill at
131k. The Amdahl prediction for a 1.55x faster attention kernel at 74.7% share
is $1/(1-0.747+0.747/1.55) = 1.41$x — which is exactly what we measure. This
is the first lever in the project that moves the quadratic coefficient $b$ of
the prefill law $t(D) = aD + bD^2$, because it makes the attention kernel
itself faster rather than changing the weight format.

At 238,400 tokens (throughput's max context), the speedup should be even
larger: the quadratic share there is 84.2%, giving an Amdahl prediction of
$1/(1-0.842+0.842/1.55) = 1.49$x.

## Correctness

Sanity check passes (both backends answer "Paris"). Greedy text output is
semantically equivalent at both 2k and 131k ("word" in all cases) but exact
tokens diverge:

- shallow (2k): same text, max|dlogprob| = 1.073
- deep (131k): semantically equivalent but different phrasing, max|dlogprob| = 1.157

The logprob delta is expected: different attention backends use different
tiling and accumulation orders, producing slightly different floating-point
results. The 1.07–1.16 max delta is within the range seen between other
numerical backend swaps, and the sanity + greedy outputs are correct. A full
KLD measurement against the BF16 reference is needed to quantify the fidelity
impact — this requires adding `attention_backend` support to `fidelity.py`
(scheduled).

## FLASHINFER

FLASHINFER crashes at boot with a C++ error (libc10). Not viable on this
image/fork combination. lribeiro uses it successfully on their fork, but
ours uses the Gilded Gnosis base which may not have the FlashInfer SM120
kernels compiled.

## Infrastructure change

Added `BLOCK_SIZE` env knob to `patches/run-qwen38-27b.sh`:
`${BLOCK_SIZE:+--block-size ${BLOCK_SIZE}}`. B12X_ATTN requires block-size
in (64, 128); the fork defaults to 16 for this model. TRITON_ATTN works at
any block size and is unaffected.
