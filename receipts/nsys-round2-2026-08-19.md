# nsys Round 2: lm_head is 15% of decode, support ops are ~20%, and prefill's tail is concat

**Date:** 2026-08-19 (late). Traces + kernel-sum CSVs in `receipts/traces/`
(`fid-prefill-cured2`, `thr-prefill-600w2`, `thr-decode-mtp2`, `thr-c4-mixed2`;
`.nsys-rep` + `.sqlite` + `_cuda_gpu_kern_sum.csv` each). Captured via the launcher's
`NSYS_PROFILE=1` + `PROFILER_CONFIG='{"profiler":"cuda"}'` + `/start_profile` window,
600 W, post-cure stack.

Method note recorded for honesty: the first capture pass produced four EMPTY windows
because the workload posted the wrong served-model name (404 on every request) — the
profiler endpoints returned 200 and nsys dutifully saved ~4 MB of nothing. Second
pass verified both endpoint HTTP codes and workload completion inline.

## throughput prefill (6x 2051-token requests)

| kernel group | share |
|---|---|
| b12x dense FP4 GEMMs (N=5120 / 17408 / 6144) | 29.1 + 9.7 + 3.3 = **42.1%** |
| **CatArrayBatchedCopy** (tensor concat) | **7.3%** |
| unified_attention | 4.8% |
| activation-quant support (copy/abs/mul) | 4.3 + 3.9 + 3.3 = **11.5%** |
| silu act_and_mul | 3.4% |

The FP4 GEMMs are less than half the window. ~19% goes to support ops that exist
only to feed them (concat + scale computation + dtype copies). This is the
quantified version of the bake-off's 67.7%-of-format-ceiling gap: the missing third
is not in the GEMMs, it is around them.

## V2 MTP decode (300-token fox)

| kernel group | share |
|---|---|
| b12x FP4 GEMMs (5120/17408/6144) | 25.1 + 9.3 + 3.3 = **37.7%** |
| **exl3_gemm_kernel<6> — the K6 lm_head** | **14.8%** (567 inst x 567 us) |
| activation-quant support (MaxNan reduce + Bf16ToFp4 + copies + div) | 7.7 + 5.8 + 5.1 + 2.0 = **20.6%** |
| GDN fused_sigmoid_gating_delta_rule | 2.4% |

Two levers fall out:

1. **lm_head decode routing.** 567 us per call on a 248,320 x 5,120 K6 matrix through
   the fused kernel. The `MIN_M=128` dispatch sends ALL decode rows to the fused
   kernel — right for the 409 body matrices, but the lm_head is 30x wider than any of
   them and b12x has a cooperative small-M K6 path. A per-matrix exception for
   lm_head is a bounded experiment with a visible 15%-of-decode prize.
2. **Activation quantization is a fifth of decode.** MaxNan amax + Bf16ToFp4 + copies
   + div are all per-token overhead to keep activations in FP4. Fusing amax into the
   TMA quant kernel (or caching scales across MTP draft steps, which reuse the same
   activations) is b12x-side work — reporting with these numbers to b12x#232/#234.

C4 mixed-batch shows the same shape with lm_head calls stretching to 1.15 ms max
under contention (14.8% share unchanged).
